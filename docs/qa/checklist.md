## Owner-reported findings (2026-11-02)

- [x] QA-01 Clearing the posts search kept the filtered list: the search box remounted on every result (`key={q}`) and its mount effect re-sent stale queries, also losing focus. It now keeps its own state and adopts only URL changes it didn't make (a nav link, back button); its own results arriving late never overwrite newer typing. It replaces the history entry instead of pushing one per pause, so Back leaves the posts page rather than stepping through partial queries. Same fix on the dashboard posts table.
- [x] QA-02 "Request to publish" was offered again after a reload although a request was pending: the page now passes the latest request's status (pending → message, rejected → "Request again", approved in the last 5 minutes → "writing unlocks within a minute" while the session's role catches up). A unique partial index allows one pending request per user, so a double click can't create two. A database that already holds two pending requests for one user can't build that index (Mongoose only reports it through the model's `index` event); find them with `db.publishrequests.aggregate([{$match:{status:"Pending"}},{$group:{_id:"$userId",n:{$sum:1}}},{$match:{n:{$gt:1}}}])` and reject the extras.
- [x] QA-03 Bell entries showed an arrow cursor: shadcn's menu items use `cursor-default`; all dropdown menu items now use a pointer.
- [x] QA-04 An approved or rejected request stayed unread in every admin's bell: reviewing a request marks all admins' notifications of it read (`src/libs/publish-request-notifications.ts`, best effort, scoped to admins so it uses the `{ recipientId, read }` index). The request route re-checks the status after writing the notifications, so a review that lands before they exist still clears them.
- [x] QA-05 `/posts/add` showed the posts-grid skeleton (inherited `posts/loading.tsx`): the editor pages have an editor skeleton; revisions and every dashboard page have a neutral page skeleton instead of article cards.

- [x] QA-06 (found by the suite) The account-deletion test failed once: after the reload, the surviving reply matched twice, though the database holds it once and the tree builder is correct. The second match had no accessible role, consistent with a hidden streamed copy during the reload; the test now asserts exactly one visible copy. ## Owner follow-up round (2026-11-02)

The owner found two blank-list bugs the pass had missed. The suite asserted that cards were in the page; Playwright's `toBeVisible()` counts an element at opacity 0 as visible, and nobody looked at screenshots after client navigations. The kit's method now covers this ("Present is not seen", `docs/kits/flow-qa/method.md` § 5), and the specs check opacity through `expectSeen()` in `e2e/fixtures.ts`.

- [x] QA-15 Clearing the posts search, or choosing Next or Previous, left the list blank under a correct "N articles" heading. The card grid faded in once per mount (`whileInView` with `once`), so cards swapped in by a client navigation stayed at opacity 0. Each card now animates on its own (`src/components/posts/ArticleGrid.tsx`), which fixes the posts list, the home page and author pages together. The search and paging specs fail on the old grid and pass on the new one.
- [x] QA-16 Votes looked wrong: the bar showed one net score, which jumps by two when a vote switches sides and goes negative. Each arrow now shows its own count. Behind it, `toggleVote()` recounts the target's totals from the live vote records (re-checking after its write, so the request that finishes last always leaves them right) instead of `$inc` after a separate read, which could drift under concurrent clicks; a concurrent duplicate create keeps or switches the vote instead of failing; the routes return the recounted totals; `{target, deleted, type}` indexes serve the counts. Counts that drifted in an existing database correct themselves on the target's next vote.
- [x] QA-17 The account page's sections didn't read as sections: each one (photo, public profile, private details, change password, data export, delete) is now a card with a heading and a description (`src/components/account/AccountCard.tsx`); the delete button no longer stretches across the card.
- [x] QA-18 Menu order: the dashboard menu is grouped into You (My Posts, Notifications, Account), Moderation (Review Queue, Comments) and Admin (Publish Requests, All Posts, Users, Categories, Uploads), highlights the current page and wraps instead of running off the screen. The avatar menu, which held only Logout, now has Write a post (authors and above), My Posts, Notifications and Account, from one shared list (`src/libs/dashboard-links.ts`).
- [x] QA-19 (found by the code review of the last commit) Test hygiene: the categories test checked the stale toast (`.last()` is the oldest with Sonner), and the phone-menu steps branched on whatever rendered and matched the footer link; a `clickNavLink()` helper now follows the device and scopes to the menu dialog.
